# Claim → evidence audit

One row per claim this tool makes in its user-facing documents: whether it is supported, what bounds it, and the test that locks it. Evidence names the suite that runs in `npm test`; CI runs the same chain plus explicit source-registry validation. A claim is never stated as supported without a row.

| 31 | `.pdf` is a supported input: the text is recovered from the document's bytes and screened by the same rules as any other copy | Yes | A PDF is a rendered page, so the text is recovered from positioned glyphs rather than from a source. Refusal is fail-closed: exit `2`, a reason on standard error, nothing on standard output, no partial extraction and no clean-run sentence for a document that was not read. `--fix` refuses a PDF | `tests/audit-pdf-extraction.mjs` (fixture generator, adversarial and refusal cases, with its own tests asserting the bytes exhibit the property each case claims); the `--fix` refusal and the refused-PDF-is-not-a-clean-run assertions in `tests/audit-fix-set.mjs`; the extension-set and document-truth locks in `tests/audit-extraction.mjs` |

## What no row claims

No row asserts completeness of detection, accuracy or truth of copy, neutrality of outcome, legal conformity, or institutional endorsement. Those are outside a local rule run by construction: the tool screens copy against documented, enabled local rules and reports what those rules find.
